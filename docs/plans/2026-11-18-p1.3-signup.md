# P1.3 Signup & Business Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One signup form creates a business, its first branch, the owner and a recovery key in one transaction; a settings page edits the business afterwards; every API body is checked by a shared Zod schema and every route names its permission.

**Architecture:** Schemas, state codes, business types and permission names in `packages/shared`. Migration `0003` in `packages/db` (new columns on `businesses` and `branches`, tables `users` and `recovery_keys`, the actor key on `entry_log`). In `apps/api`: password hashing, a Zod body pipe, a permission guard with a swappable session resolver, a signup module and a settings module. In `apps/web`: public and app layouts, signup, recovery key and settings pages.

**Tech Stack:** PostgreSQL 18, Drizzle 0.45 / drizzle-kit 0.31, NestJS 12, Zod 4, React 19, TanStack Router, React Hook Form, i18next, Vitest 5 + Testcontainers.

**Spec:** `docs/plans/2026-11-18-p1.3-signup-design.md`. ADRs 0003, 0007, 0009, 0027, 0028; new 0034, 0035.

## Global Constraints

- Tenant rules (ADR 0027): `id()`, `businessId()`, `createdAt()`, `tenantPolicy()`, hand-written `FORCE`, composite keys, `unique (business_id, id)` on referenced tables. The guard test must pass unchanged except for listed exceptions.
- Generate migration `0003` only after rebasing onto `main` at merge time (fast-track rule); during the work it can be regenerated freely, it isn't on `main`.
- Entry log: only through `recordEntry`; money as paise.
- Never log an error object: `describeError`. Never log a body, email, phone, password or recovery key.
- Client errors are `HttpException`s with a `code`. The web app translates codes.
- Every string in `en`, `hi`, `hi-Latn`. Tokens only, whole Tailwind class names, native `<dialog>`, `useShortcut`.
- No `pnpm dev` / `db:up` / `app:up` / Chrome without asking the parent session (one app at a time). No `pnpm approve`.
- Commits: Conventional, no AI attribution; gitleaks from the main checkout with `--log-opts="origin/main..feat/p1.3-signup"`; personal-data search before each commit.
