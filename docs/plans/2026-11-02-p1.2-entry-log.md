# P1.2 Entry Log Recording Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An append-only tenant table `entry_log`, one write helper `recordEntry(tx, entry)` that every module calls inside its own transaction, and a guard test widened to close the P1.1 review gaps.

**Architecture:** `entryLog` is declared in `packages/db/src/schema.ts` with the P1.1 helpers. Migration `0002_entry_log.sql` is generated by drizzle-kit, then `FORCE ROW LEVEL SECURITY` and `REVOKE UPDATE … FROM app_runtime` are added by hand. `packages/db/src/entry-log.ts` holds the action list and `recordEntry`. The guard (`src/tenancy-guard.test.ts`) moves from direct grants to effective privileges, covers every non-system schema, and gains rules for the business key, append-only tables and functions. No API or web changes.

**Tech Stack:** PostgreSQL 18, drizzle-orm 0.45 (`jsonb`, `foreignKey`), drizzle-kit 0.31, `pg` 8, Vitest 5 + Testcontainers (`startTestDatabase()` from `src/testing.ts`).

**Spec:** `docs/plans/2026-11-01-p1.2-entry-log-design.md`; ADR 0028 (this design), ADRs 0007, 0019, 0027.

## Global Constraints

- Roles: `app_owner` (migrations, owns tables, no CREATEROLE), `app_runtime` (the app). On `entry_log`, `app_runtime` has **only SELECT and INSERT**.
- Tenant table rules (ADR 0027): `id()`, `businessId()`, `createdAt()`, `tenantPolicy(t.businessId)`, hand-written `FORCE ROW LEVEL SECURITY`, composite keys into tenant tables.
- Never edit migrations `0000` or `0001`; the new one must be `0002` and newer than `main`'s.
- Error codes asserted: `42501` (insufficient privilege, RLS `WITH CHECK`), `22P02` (invalid uuid text), `23503` (foreign key). Drizzle wraps driver errors: use the existing `failsWith(code)` shape (`{ cause: { code } }`); a raw `pg` Pool error has `code` directly.
- Money inside `before`/`after` is integer paise (ADR 0008).
- Docker Desktop must be running for the tests. Before each commit: gitleaks staged scan + personal-data search (`docs/devops/git-workflow.md`, Secrets). Conventional Commits, **no AI attribution lines** (`CLAUDE.md` rule 6).
- Write files with the Write/Edit tools or Git Bash, never PowerShell `Set-Content`/`Out-File`.

## Decisions in this plan (and why)

| Decision | Why |
| --- | --- |
| `recordEntry` validates and `JSON.stringify`s `before`/`after` itself before the insert | The "throws, nothing written" rule then doesn't depend on when Drizzle serialises. |
| The guard's function checks are a second query (`findFunctionViolations`), not more rows in the table query | Its rows are functions, not tables; mixing them would blur the `Violation.table` field. |
| Role and schema probes are created with `server.adminUrl` (the container superuser) | `app_owner` can't create roles, and may not create schemas. The probes still check what `app_runtime` can do. |
| Probe tables outside `public` are reported schema-qualified (`c.oid::regclass::text`) | `public` tables keep their bare names, so the existing expected lists don't change. |

## Review Focus

1. **A business-wide action with no branch** (`branchId` omitted): the row is written with `branch_id` NULL; the composite key must not refuse it (Task 1, test `records a row with every field`).
2. **Logging at signup** (`withNewBusiness`): a `recordEntry` call after the `businesses` row is inserted must succeed; before it, the business key refuses it with `23503` (Task 1).
3. **A malformed `actorId`** (e.g. `'staff-1'` from untyped code): refused with `22P02`, nothing written (Task 1).
4. **A blank reason on an action that doesn't need one:** stored as NULL, not `''` or `'   '` (Task 1).
5. **Two entries in one transaction:** `now()` is the transaction's start time, so both share `created_at`; their `id`s (UUIDv7, monotonic within a session in PostgreSQL 18) still sort in insertion order, which is what the viewer (P2.6) will order by (Task 1).

- Produces (`schema.ts`): `entryLog` with columns `id`, `businessId` (default `app_current_business_id()`), `branchId`, `actorId`, `action`, `entityType`, `entityId`, `reason`, `before`, `after`, `createdAt`; composite key `entry_log_branch_fk` `(business_id, branch_id) → branches(business_id, id)`.
- Produces (`entry-log.ts`):
  - `ENTRY_ACTIONS = { 'stock.adjusted': { reasonRequired: true } } as const satisfies Record<string, { reasonRequired: boolean }>`
  - `type EntryAction = keyof typeof ENTRY_ACTIONS`
  - `interface EntryInput { actorId: string | null; action: EntryAction; entityType: string; entityId: string; branchId?: string; reason?: string; before?: Record<string, unknown>; after?: Record<string, unknown> }`
  - `recordEntry(tx: Transaction, entry: EntryInput): Promise<void>`
- `index.ts` also exports `entryLog`, `ENTRY_ACTIONS`, `recordEntry`, `type EntryAction`, `type EntryInput`.

- [ ] **Step 1: Write the failing tests** in `src/entry-log.test.ts`

Setup like `tenancy.test.ts`: `startTestDatabase()`, `runtime = createDatabase(server.runtimeUrl, vi.fn())`, an owner `Pool`, the same `signUp(name)` helper and `failsWith(code)`. Create `a` and `b`. A local `adjust(overrides?: Partial<EntryInput>): EntryInput` returns `{ actorId: '0190f0f0-0000-7000-8000-00000000a001', action: 'stock.adjusted', entityType: 'item', entityId: '0190f0f0-0000-7000-8000-00000000e001', reason: 'Damaged in transit', before: { quantity: 10 }, after: { quantity: 8 }, ...overrides }`. Read rows back with `withBusiness(…, (tx) => tx.select().from(entryLog))`. Tests:

- `records a row with every field`: in A, `recordEntry(tx, adjust())` → one row equal to the input plus `businessId: a.businessId`, `branchId: null`; `createdAt` is a `Date` within 5 s of now. Then with `branchId: a.branchId` → that row has `branchId: a.branchId`.
- `rolls back with the action it describes`: `withBusiness(a…)` that records an entry then throws `new Error('boom')` → rejects `'boom'`; A's row count unchanged.
- `keeps businesses apart`: B sees none of A's rows; inside B, `tx.insert(entryLog).values({ businessId: a.businessId, action: 'stock.adjusted', entityType: 'item', entityId: … })` → `failsWith('42501')`.
- `fails with no business set`: `recordEntry` inside `runtime.db.transaction(…)` (no `withBusiness`) → `failsWith('42501')` (PostgreSQL runs the RLS check, where `NULL = NULL` isn't true, before the NOT NULL check).
- `it.each([undefined, '', '   '])('refuses stock.adjusted with reason %j')`: rejects with `'Entry action "stock.adjusted" needs a reason'`; A's row count unchanged.
- `stores a blank optional reason as null`: needs an action without `reasonRequired`, so the test adds a test-only case through a cast: `recordEntry(tx, { ...adjust(), action: 'test.optional' as EntryAction, reason: '  ' })` → stored `reason` is `null`. (`recordEntry` treats an unknown action as `reasonRequired: false`; this test pins that.)
- `it.each(['update entry_log set reason = null', 'delete from entry_log', 'truncate entry_log'])('refuses to let the runtime role run %s')`: `runtime.pool.query(sql)` → rejects `{ code: '42501' }`.
- `refuses a branch from another business`: in B, `recordEntry(tx, adjust({ branchId: a.branchId }))` → `failsWith('23503')`.
- `refuses a value that cannot become JSON`: `adjust({ before: { quantity: 10n } })` → rejects (`TypeError`); row count unchanged.
- `refuses a malformed actor ID`: `adjust({ actorId: 'staff-1' })` → `failsWith('22P02')`.
- `logs at signup once the business exists`: `withNewBusiness(runtime.db, async (tx, id) => { await tx.insert(businesses).values({ id, name: 'Shop C' }); await recordEntry(tx, adjust()); })` resolves; a second `withNewBusiness` that calls `recordEntry` *before* inserting the business → `failsWith('23503')`.
- `orders two entries in one transaction by id`: two `recordEntry` calls in one `withBusiness` → equal `createdAt`; ids compare `first.id < second.id` (string compare is fine for UUIDv7).

- [ ] **Step 1: Write the failing probes and checks**

Add to the probe test (cleanup in its `finally`, using an `admin` Pool on `server.adminUrl`: `drop schema if exists probe_schema cascade`, `drop owned by probe_role`, `drop role if exists probe_role`, `drop function if exists probe_definer()`):
- `probe_no_business_fk`: `columns: 'business_id uuid not null'` → `{ rule: 'business_fk' }`.
- `probe_append_only`: a correct table, checked with `findTenancyViolations(owner, [...APPEND_ONLY, 'probe_append_only'])` → `{ rule: 'append_only' }`.
- `probe_inherited_delete`: a correct table; admin runs `create role probe_role`, `grant probe_role to app_runtime`; owner runs `grant delete on probe_inherited_delete to probe_role` → `{ rule: 'privileges' }`. Also `findRoleMemberships(owner)` → `['probe_role']`.
- `probe_schema.probe_other`: admin `create schema probe_schema authorization app_owner`; owner creates it with `enable: false` → `{ table: 'probe_schema.probe_other', rule: 'rls' }`.
- `probe_definer()`: owner `create function probe_definer() returns int language sql security definer as 'select 1'` → `findFunctionViolations` contains `{ name: 'probe_definer', rule: 'definer_public' }`.
- Pin: owner `alter function app_current_business_id() security definer`, then `findFunctionViolations` contains `{ name: 'app_current_business_id', rule: 'function_pin' }` (and `definer_public`); restore with `security invoker` in `finally`.

The new expected rows go into the existing sorted `toEqual` list in `collate "C"` order. Add real-schema tests: `findFunctionViolations(owner)` → `[]`; `findRoleMemberships(owner)` → `[]`.

- [ ] **Step 3: Change the queries**

- `tables`: every schema except `information_schema`, `pg_%` and the listed `NOT_TENANT_SCHEMAS = ['drizzle']` (comment: drizzle-kit's migration history; `pgboss` joins in P2.7); select `c.oid::regclass::text as relname`. Same for the `kind` rule.
- `privileges`: drop `aclexplode`; a row when `has_table_privilege('app_runtime', t.oid, p)` for any `p` in `DELETE`, `TRUNCATE`, `REFERENCES`, `TRIGGER`, `MAINTAIN` (covers PUBLIC and inherited grants).
- `append_only`: `t.relname = any($1)` and `has_table_privilege('app_runtime', t.oid, 'UPDATE')`; pass `appendOnly` as `$1`.
- `business_fk`: tables other than `businesses` that have a `business_id` column and no foreign key with `columns = {business_id}` into `businesses` with `referenced = {id}`.
- `findFunctionViolations`: over `pg_proc` in the same schemas: `definer_public` when `prosecdef` and `aclexplode(coalesce(proacl, acldefault('f', proowner)))` has grantee `0` with `EXECUTE`; `function_pin` when `app_current_business_id` is missing or not (`prosecdef = false`, `provolatile = 's'`, language `sql`, `prosrc` equal to ` select nullif(current_setting('app.business_id', true), '')::uuid ` (with the surrounding spaces, as written in `0001`)).
- `findRoleMemberships`: `select r.rolname from pg_auth_members m join pg_roles r on r.oid = m.roleid where m.member = 'app_runtime'::regrole`.
