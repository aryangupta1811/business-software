# P0.7 Design System — Design Spec

**Status:** approved section by section by the owner on 2026-10-31; this file awaits the owner's review before the implementation plan is written.
**Task:** P0.7 in `docs/PROGRESS.md`. **Related ADRs:** 0003 (React SPA, shadcn/ui on Radix, Tailwind), 0023 (web build, Caddy, CSP, three languages). New ADRs: 0025 (design system), 0026 (keyboard shortcuts and native dialog).

## 1. Goal and success criteria

The web app gets its own look and the building blocks every later screen uses, so P1.3 (signup) and later tasks make **no design decisions of their own**: they reuse tokens and components and add new components in the same style.

Done means:
- design tokens (colour, type, spacing, radius, shadow, focus) for light and dark, in one place;
- IBM Plex fonts self-hosted, light/dark switch with no flash, favicon;
- seven restyled base components, the app layout, and the restyled existing pieces;
- a keyboard-shortcut module with a help panel;
- a `/design` showcase page;
- automatic tests for readability (contrast), shortcuts, theme and components; no CSP violations in the built app through Caddy.

## 3. The look: design tokens

All tokens are CSS custom properties in `apps/web/src/styles.css`, defined on `:root` (light) and on `:root.dark` (dark), and exposed to Tailwind 4 through `@theme inline`, so components use classes like `bg-surface text-muted`. Colours are written as hex so the contrast test can read them.

### Colours

| Token | Use | Light | Dark |
| --- | --- | --- | --- |
| `background` | page | `#f5f5f7` | `#000000` |
| `sidebar` | sidebar | `#fbfbfd` | `#0f0f10` |
| `surface` | cards, panels, inputs | `#ffffff` | `#1c1c1e` |
| `surface-muted` | secondary buttons, selected nav item, hover | `#e8e8ed` | `#2c2c2e` |
| `text` | main text | `#1d1d1f` | `#f5f5f7` |
| `muted` | secondary text, labels | `#6e6e73` | `#a1a1a6` |
| `border` | hairlines, table rows | `#e8e8ed` | `#2c2c2e` |
| `input-border` | edges of inputs | `#8e8e93` | `#6e6e73` |
| `primary` | primary button background | `#0071e3` | `#0071e3` |
| `on-primary` | text on primary | `#ffffff` | `#ffffff` |
| `accent` | links, focus ring, selected state, accent text | `#0071e3` | `#2997ff` |
| `success` / `success-soft` | paid, OK (text / badge background) | `#1d7f45` / `#e8f5ec` | `#30d158` / `#0f2a19` |
| `warning` / `warning-soft` | udhaar due, low stock | `#b25000` / `#fff2e5` | `#ff9f0a` / `#3a2a12` |
| `danger` / `danger-soft` | error, cancelled | `#d70015` / `#ffebed` | `#ff453a` / `#3a1414` |

Status colours carry meaning only, never decoration, and always come with a word or icon.

### Readability rules (enforced by a test)

The contrast test (section 8) reads the tokens and checks, in both modes:
- `text` on `background` and on `surface`: at least **7:1**;
- every other text colour (`muted`, `accent`, `success`, `warning`, `danger`, `on-primary` on `primary`, status text on its `-soft` background) on the backgrounds it is used on: at least **4.5:1** (WCAG AA);
- `input-border` against `surface`, and the focus ring (`accent`) against `background` and `surface`: at least **3:1** (WCAG non-text contrast).

The hex values above were chosen to pass. If one turns out to fail, it is darkened or lightened just enough to pass; **the test is the rule, not the table**.

### Type

- **Fonts:** IBM Plex Sans (Latin) and IBM Plex Sans Devanagari, from the `@fontsource` npm packages, bundled by Vite into hashed assets (served with the long cache Caddy already sets). Weights **400, 500, 600** only; only the Latin and Devanagari subsets. No Google Fonts request (CSP `font-src 'self'`).
- **Sizes:** 13 px small labels, **15 px body**, 17 px section titles, 22 px page titles, 28 px big numbers. **Nothing below 13 px.**
- **Line height:** 1.5; **1.6 when the language is Hindi** (`:lang(hi)`), so Devanagari marks don't touch the next line. No fixed-height boxes that clip text.
- **Money:** `font-variant-numeric: tabular-nums` everywhere numbers are shown; money right-aligned in tables.

### Shape, spacing, depth, focus

- **Radius:** 8 px for cards, buttons, inputs, nav items; 6 px for badges and small chips; 4 px for key chips.
- **Spacing:** 4 px grid (Tailwind's default scale).
- **Control height:** 40 px (buttons, inputs); 32 px for small buttons.
- **Depth:** light mode cards have a soft two-layer shadow (`0 1px 2px rgb(0 0 0 / .04), 0 6px 20px rgb(0 0 0 / .05)`) and no border; dark mode has no shadows, cards are lighter than the background.
- **Focus:** a 2 px `accent` ring with a 2 px offset on every focusable element on keyboard focus (`:focus-visible`). Never removed.

## 4. Layout and light/dark switching

```
┌────────────┬──────────────────────────────────────────────────────┐
│ ▣ App name │  Page title     ● Connected   English·हिन्दी·Hinglish  ☀ │
│            ├──────────────────────────────────────────────────────┤
│ ▸ Home     │  page content                                        │
│            │                                                      │
└────────────┴──────────────────────────────────────────────────────┘
```

- **Sidebar** (left, fixed width): app name with the favicon mark at the top, then navigation. Today only **Home**; each later module adds its item with its shortcut chip.
- **Top bar:** page title on the left; on the right the connection badge (dot + word), the language switcher (each name in its own script) and the sun/moon button.
- **Screen sizes:** designed for 1366×768 and larger; usable down to 1024 px wide. No phone layout.
- **Icons:** `lucide-react` (SVG components bundled into the app).
- **Theme:** light by default. The sun/moon button toggles a `dark` class on `<html>` and saves `light`/`dark` in `localStorage`. A tiny classic script, `public/theme-init.js`, loaded from `<head>` before the app (an external file, because the CSP's `script-src 'self'` blocks inline scripts), applies the saved mode before the first paint, so there is no flash. Every storage access is wrapped in `try/catch`; if storage is unavailable the app is light and the button still works for the session. Per-person preference waits for logins (P1.4) and is not part of P0.7.
- **Favicon:** `public/favicon.svg` (a `primary` blue square, 8 px-style corners, white ₹) and `public/favicon.ico` (32 px fallback). This fixes `/favicon.ico` returning the SPA HTML.

## 6. Keyboard shortcuts

**Module** (`src/shortcuts/`): a provider holds a registry; components register shortcuts with a hook while mounted and they are removed on unmount. A shortcut has: `keys` (e.g. `F2`, `Alt+H`, `?`), a translation key for its description, a `group` (`general`, `navigation`, later `billing`), and an action.

**Rules:**
1. **Typing is safe.** When focus is in an `input`, `textarea`, `select` or `contenteditable`, shortcuts without a modifier (letters, `?`) don't fire. Function keys `F1`–`F12` (except the reserved ones) and `Esc` do fire there, so billing can use F-keys while the cursor stays in the scanner's search box.
2. **Physical keys for letters.** Letter and digit shortcuts with a modifier match `KeyboardEvent.code` (e.g. `KeyH`), so `Alt+H` works with a Hindi keyboard layout, where `event.key` would be "ह". Function keys, `Esc` and `?` match `event.key`.
3. **Reserved browser keys are never used:** `F5`, `F11`, `F12`, `Ctrl+T/W/N/R/L`. Registering one is an error.
4. **No clashes:** registering keys that are already active is an error (thrown in development, caught by tests).
5. **Visible:** actions that have a shortcut show its `Kbd` chip.

**Registered in P0.7:** `?` opens the help panel; `Alt+H` goes Home. Billing F-keys come with P1.13.

**Help panel:** the browser's native `<dialog>` opened with `showModal()` (built-in focus handling, `Esc` to close, page behind made inert), styled with the tokens. It lists the active shortcuts grouped, with descriptions in the current language. Native `<dialog>` is the pattern for later modal dialogs too, because Radix Dialog (via `react-remove-scroll`) injects a runtime `<style>` element, which the CSP's `style-src 'self'` blocks.

## 7. CSP and security

- No CSP change. Fonts and icons are bundled; the theme script is an external file; no inline `<style>` or `style=""` in HTML.
- Radix Tooltip positions with inline styles set from JavaScript (CSSOM), which `style-src 'self'` allows; this is checked in the built app, not assumed.
- No new secrets, no `VITE_` variables.

## 8. Testing and verification

**Automatic (Vitest, jsdom):**
- **Contrast:** parses the token block of `styles.css` and checks every pair listed in section 3, in both modes.
- **Shortcuts:** one test per rule (typing safe; F-keys and `Esc` in inputs; `event.code` on a Hindi layout; reserved keys rejected; clash rejected; unregister on unmount; help panel lists only active shortcuts in the current language; `?` opens and `Esc` closes it; `Alt+H` navigates Home).
- **Theme:** toggle switches the class and the stored value; stored `dark` is applied by `theme-init.js`; storage that throws falls back to light without crashing; the button's label is translated.
- **Components:** each variant renders; Input error state sets `aria-invalid` and `aria-describedby`; Tooltip appears on focus.
- **Languages:** the existing locale tests (all keys in three files, no Devanagari in Hinglish) cover the new strings.
- All existing web tests are kept, updated only where markup changes.

**Real app:**
- `pnpm app:up`; open `http://127.0.0.1:8080/design` in Chrome in light and dark × English, Hindi, Hinglish; the console shows **no CSP violations**; screenshots of the six combinations go to the owner for review.
- `scripts/ci/smoke.sh` gains a check that `/favicon.ico` returns an image content type, not HTML.
- `pnpm check` passes; CI is green.
