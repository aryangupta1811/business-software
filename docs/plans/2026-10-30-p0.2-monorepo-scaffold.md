# P0.2 Monorepo Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pnpm workspace with strict TypeScript, ESLint, Prettier and Vitest, where `pnpm check` runs every check, and `packages/shared` holds the first money helpers (`parseRupees`, `formatPaise`), written test-first.

**Architecture:** One pnpm workspace. The root holds the shared tool config (TypeScript base, ESLint, Prettier) and scripts that run each package's checks. `packages/shared` is the first package: pure TypeScript with no framework, Node or browser APIs, so both the web app and the API can use it. `apps/web` and `apps/api` are not created here: P0.4 and P0.5 generate them with their real tools.

**Tech Stack:** Node 24, pnpm 12, TypeScript (strict), ESLint (flat config, typescript-eslint type-aware rules), Prettier, Vitest.

**Spec:** `docs/PROGRESS.md` task P0.2; ADR 0002 (TypeScript monorepo), ADR 0008 (money in integer paise), ADR 0013 (testing).

## Global Constraints

- Node `>=24` (installed: 24.18). pnpm pinned with `"packageManager": "pnpm@12.16.1"` in the root `package.json`.
- Install the latest stable version of each tool; the lockfile records the exact versions. A dependency used by more than one package goes in the pnpm `catalog:` (one version for the whole repo). If typescript-eslint's peer range doesn't accept the newest TypeScript, use the newest TypeScript it accepts.
- Strict TypeScript from day one (ADR 0002): `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`, `forceConsistentCasingInFileNames`, `skipLibCheck`; `target`/`lib` `ES2023`; `module`/`moduleResolution` `NodeNext`; `noEmit`.
- `packages/shared` contains no React, NestJS, Node or DOM code (ADR 0002). Its tsconfig sets `"types": []` and no DOM lib, so using such APIs fails the type check.
- Money is whole paise in a plain `number` that must be a safe integer (ADR 0008). Converting to and from rupees never goes through floating-point maths. The display format is `₹1,23,456.78` (Indian digit grouping).
- Scripts must run in Windows (cmd/PowerShell) and on Linux CI: no single-quoted arguments, no `rm -rf`, no bash-only syntax.
- Before each commit: the gitleaks staged scan and the personal-data `git grep` from `docs/devops/git-workflow.md` (Secrets). Docker Desktop must be running.
- Conventional Commits; **no AI attribution lines** in commits or PRs (`CLAUDE.md` rule 6).

## Decisions in this plan (and why)

| Decision | Why |
| --- | --- |
| No `apps/web` or `apps/api` folders yet; the workspace already includes `apps/*` | An empty app would be throw-away code. P0.4 creates the API with the NestJS tools and P0.5 creates the web app with Vite. |
| `packages/shared` is consumed as TypeScript source (`"exports": "./src/index.ts"`), not built | No build step to forget or run in watch mode. Vite and Vitest read TypeScript directly. Node can't run it from source (found in the final review), so P0.4 must make the API use a compiled `shared`. |
| `NodeNext` modules, so relative imports end in `.js` (`./money.js`) | Runs under Vite and Vitest as it is, and under Node once compiled: tsc keeps the `.js` paths, which then point at real files. |
| One ESLint and one Prettier config at the root | Same rules everywhere. Type-aware linting (`projectService`) finds each package's own tsconfig. |
| Prettier formats code and config, not Markdown (`*.md` ignored) | Reformatting every doc would bury this PR's real changes. |
| Each package has its own `typecheck` and `test` scripts; the root runs them with `pnpm -r` | A package checks itself. The root just calls everyone. |
| pnpm `minimumReleaseAge` of one day | A hijacked package version is usually caught and removed within hours. Waiting a day before installing new releases avoids most of these supply-chain attacks. |
| Build scripts of dependencies stay blocked unless something fails without them | pnpm blocks dependencies' install scripts by default. Approve one only with a reason. |
| `parseRupees` returns `null` for bad input; `formatPaise` throws `RangeError` | Bad typing at the counter is expected, so the screen shows a message. A non-integer amount in code is a bug, so it should fail loudly. |
| `parseRupees` refuses (never guesses) commas, `₹`, signs, more than 2 decimals, non-ASCII digits | A refused amount asks the user to fix it. A guessed amount could silently save a wrong bill. |

Not in this task: git hooks; CI (P0.6); an `allocate()` helper for splitting discounts (after Module 02 is finalized); a "branded" `Paise` type that the compiler keeps apart from other numbers (raise at P1.12, the GST engine).

## Review Focus

1. **Checks that never fail prove nothing.** A planted type error, lint error, formatting error and Node-only API must each make its command fail. → Task 1, Step 6.
2. **Amounts typed by a person:** spaces, commas, `₹`, `+`/`-`, three decimals, Devanagari digits (`१२५`), scientific notation. Each must give `null`, never a guessed amount. → Task 2 tests.
3. **Floating-point traps:** `0.29 * 100` is `28.999999999999996` and `1.1 * 100` is `110.00000000000001`. `'0.29'` must give exactly `29` and `'1.1'` exactly `110`. → Task 2 tests.
4. **Very large amounts:** at `Number.MAX_SAFE_INTEGER` the result must be exact, and past it the helper must refuse instead of returning a rounded value. → Tasks 2 and 3 tests.
5. **Negative and zero amounts on screen** (refunds, udhaar credit): `-₹1,250.00`, `₹0.00`, and `-0` showing as `₹0.00`, not `-₹0.00`. → Task 3 tests.

### Task 2: `parseRupees`, test-first

**Files:**
- Create: `packages/shared/src/money.test.ts`
- Modify: `packages/shared/src/money.ts`, `packages/shared/src/index.ts`

**Interfaces:**
- Consumes: `Paise` (Task 1).
- Produces: `parseRupees(input: string): Paise | null`, exported from `@business-software/shared`.

- [ ] **Step 1: Write the failing tests** in `money.test.ts`:
  ```ts
  import { describe, expect, it } from 'vitest';
  import { parseRupees } from './money.js';

  describe('parseRupees', () => {
    it.each([
      ['125', 12500], ['125.5', 12550], ['125.50', 12550], ['0.05', 5], ['0', 0],
      ['007', 700], ['.5', 50], ['125.', 12500], [' 125.50 ', 12550],
      ['0.29', 29], ['1.1', 110], ['90071992547409.91', Number.MAX_SAFE_INTEGER],
    ])('reads %j as %i paise', (input, paise) => {
      expect(parseRupees(input)).toBe(paise);
    });

    it.each([
      '', '   ', '.', '1.005', '12.555', '12.500', '-5', '+5', '1,250', '₹125', '12 .5',
      '1e3', 'abc', '0x10', 'Infinity', 'NaN', '१२५', '90071992547409.92',
    ])('refuses %j', (input) => {
      expect(parseRupees(input)).toBeNull();
    });
  });
  ```

- [ ] **Step 2: Run `pnpm test` from the root.** Expected: FAIL, because `parseRupees` is not exported. The root command exits non-zero (a failing test fails the whole check).

- [ ] **Step 3: Implement `parseRupees(input: string): Paise | null` in `money.ts`.** Trim, then match `^(\d*)(?:\.(\d{0,2}))?$` with at least one digit in total. Paise = `Number(rupees) * 100 + Number(paise.padEnd(2, '0'))`, so only whole numbers are multiplied. Return `null` unless the result passes `Number.isSafeInteger`. Don't run `parseFloat` or `Number()` on the whole input: that is where `0.29` becomes `28.999…`. Export it from `index.ts`.

- [ ] **Step 4: Run `pnpm check`.** Expected: PASS, 30 tests.

- [ ] **Step 5: Scan and commit.** `git commit -m "feat(shared): parse typed rupee amounts into paise"`

### Task 3: `formatPaise`, test-first

**Files:**
- Modify: `packages/shared/src/money.test.ts`, `packages/shared/src/money.ts`, `packages/shared/src/index.ts`

**Interfaces:**
- Consumes: `Paise` (Task 1).
- Produces: `formatPaise(paise: Paise): string`, exported from `@business-software/shared`.

- [ ] **Step 1: Write the failing tests** (add `formatPaise` to the import):
  ```ts
  describe('formatPaise', () => {
    it.each([
      [0, '₹0.00'], [5, '₹0.05'], [12550, '₹125.50'], [12345678, '₹1,23,456.78'],
      [98765432100, '₹98,76,54,321.00'], [Number.MAX_SAFE_INTEGER, '₹9,00,71,99,25,47,409.91'],
      [-125000, '-₹1,250.00'], [-0, '₹0.00'],
    ])('shows %i paise as %s', (paise, text) => {
      expect(formatPaise(paise)).toBe(text);
    });

    it.each([12.5, Number.NaN, Number.POSITIVE_INFINITY, 2 ** 53])('throws for %d', (paise) => {
      expect(() => formatPaise(paise)).toThrow(RangeError);
    });
  });
  ```
  These strings are the spec (ADR 0008). If `Intl` prints something else (another minus sign, a space after `₹`), stop and report. Don't edit the expected strings to match.

- [ ] **Step 2: Run `pnpm test`.** Expected: FAIL, because `formatPaise` is not exported.

- [ ] **Step 3: Implement `formatPaise(paise: Paise): string` in `money.ts`.** Throw `RangeError` unless `Number.isSafeInteger(paise)`. Build the decimal string with string operations only: `String(Math.abs(paise)).padStart(3, '0')`, then insert the `.` before the last two digits and add `-` when the amount is below zero. `-0` is not below zero, so it shows as `₹0.00`. Pass that string to a module-level `new Intl.NumberFormat('en-IN', { style: 'currency', currency: 'INR' })`. `format()` accepts decimal strings exactly, so the amount never becomes a float. Export it from `index.ts`.

- [ ] **Step 4: Run `pnpm check`.** Expected: PASS, 42 tests.

- [ ] **Step 5: Scan and commit.** `git commit -m "feat(shared): format paise as rupees with indian digit grouping"`
