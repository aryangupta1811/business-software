# P0.5 Web Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A React app in `apps/web` with a header (server connection badge, English/Hindi/Hinglish switch) and a home page, run by `pnpm dev` next to the API, and by `pnpm app:up` as a Caddy container at http://127.0.0.1:8080 that also passes `/api` to the `api` container.

**Architecture:** Vite builds a single-page app into static files (ADR 0003). In development, Vite's dev server proxies `/api` to the API on `127.0.0.1:3000`; in Compose (and later on EC2), Caddy serves the files and reverse-proxies `/api/*` to `api:3000`, so the browser only ever talks to one origin (ADR 0011). The browser needs no configuration at all: every request is a relative `/api/...` URL.

**Tech Stack:** Vite 8.3, React 19.3, TanStack Router 1.170 (file-based, `@tanstack/router-plugin`), TanStack Query 5.105, i18next 26 + react-i18next 17, Tailwind CSS 4.3 (`@tailwindcss/vite`), Vitest 5 + jsdom + Testing Library, ESLint plugins react-hooks / jsx-a11y / react-refresh, Caddy 2.11 (Docker image), Docker Compose.

**Spec:** `docs/PROGRESS.md` task P0.5; ADRs 0001 (online-first), 0003 (React SPA and its libraries), 0011 (one domain, Caddy), 0013 (testing), 0018 (lint, catalog), 0020 (build and image conventions); `docs/devops/secrets.md` (browser rule); Module 00 #25 as changed on 2026-10-30 (English, Hindi **and Hinglish**).

## Global Constraints

- **No `VITE_` variables.** Nothing in `apps/web` reads `import.meta.env.VITE_*`; the API is always the relative path `/api` (`docs/devops/secrets.md`, rule 3).
- Three interface languages: `en` (English), `hi` (Hindi, Devanagari), `hi-Latn` (Hinglish: Hindi in Latin letters). Default `en`. Language names are always shown in their own script: `English`, `हिन्दी`, `Hinglish`.
- Every visible string comes from `src/i18n/locales/*.json`; `t()` keys are type-checked against `en.json`.
- Published ports bind `127.0.0.1` only. Containers run as non-root users.
- `pnpm lint`, `pnpm typecheck` and `pnpm test` work on a fresh clone with no build: the generated `src/routeTree.gen.ts` is committed.
- New `.ts`/`.tsx` files sit inside a tsconfig `include`. Any new dependency install script: decide in `pnpm-workspace.yaml` `allowBuilds` with a reason.
- Shared tool versions (typescript, vitest, @types/node) use `catalog:`.
- Hand-written app (no `create-vite`); Tailwind only as plumbing (tokens, fonts and shadcn/ui are P0.7).
- Before each commit: gitleaks staged scan + personal-data `git grep` (`docs/devops/git-workflow.md`). Conventional Commits. **No AI attribution lines** (`CLAUDE.md` rule 6).

## Decisions in this plan (and why)

| Decision | Why |
| --- | --- |
| Caddy serves the built app in Compose, same as on EC2 | One web server to learn; local setup matches production (ADR 0011). Rejected: nginx, `vite preview` (not a production server). |
| `caddy` image is Alpine | Caddy is a single static Go binary, so the musl concern that ruled Alpine out for Node and PostgreSQL (ADRs 0019, 0020) doesn't apply. |
| File-based routes, `routeTree.gen.ts` committed, excluded from lint and Prettier | TanStack's recommended setup, with automatic per-page code splitting. Committing keeps the no-build rule. Rejected: code-based routes (hand wiring grows with every screen). |
| Hinglish uses the BCP 47 tag `hi-Latn` | The standard tag for "Hindi in Latin script"; `<html lang="hi-Latn">` is meaningful to browsers and screen readers. |
| i18next `load: 'currentOnly'`, `fallbackLng: 'en'` | By default i18next would fall back from `hi-Latn` to `hi`, showing Devanagari to someone who chose Latin letters. |
| Language saved in `localStorage` (`language` key) | No logins yet. P1.4 moves it to the user's profile. |
| `fetchReadiness()` never throws, returns one of three states | The badge shows a state, not an error; a 5-second timeout means it never stays on "checking". |
| `/assets/*` (hashed files) cached for a year, immutable, and a missing one is a 404; every other path falls back to `index.html` with `no-cache` | Refreshing a deep link works, a new deploy is picked up on the next load, and an old tab asking for a deleted chunk gets a 404 instead of HTML cached for a year. |
| Strict Content-Security-Policy from Caddy (`default-src 'self'` …) | The built app needs nothing from other origins, so the strictest policy costs nothing now and blocks injected scripts. Dev mode has no CSP (Vite injects inline scripts). |
| jsdom for component tests | Closest to a real browser for Testing Library. Rejected: happy-dom (faster, less faithful). |
| Playwright waits for the first real flow (P1.3) | No user flow exists yet. |
| `web` has no `depends_on` | If `api` is down, the page still loads and shows "can't reach the server", which is the point of the badge. |

## Review Focus

1. **Deleted chunk after a redeploy** (old tab, `/assets/index-old.js`): must be a 404, never `index.html` with an immutable cache header. Checked with `curl -I` in Task 5.
2. **Refreshing a deep link** (`/anything`) in the container: returns `index.html` (`no-cache`), and the router shows the not-found page. Task 2 test + Task 5 curl.
3. **`localStorage` throws or holds junk** (private window, blocked storage, old value): the app starts in English and doesn't crash. Task 4 tests.
4. **A Hinglish string missing:** shows English, not Devanagari. Task 4 test.
5. **API answers with a proxy error page, non-JSON, or hangs:** the badge shows "can't reach the server" within 5 s, never stuck on "checking". Task 3 tests.
