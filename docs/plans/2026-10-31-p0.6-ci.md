# P0.6 CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every pull request and every push to `main` runs, on a clean Linux machine: format, lint, type-check, all tests (with real PostgreSQL), the build, a secrets scan, a PR-title check, a migration-order check, and a Docker Compose smoke test of the real images. `main` only accepts a PR whose checks all pass.

**Architecture:** One workflow, `.github/workflows/ci.yml`, with five parallel jobs (`check`, `secrets`, `pr-title`, `migrations`, `smoke`). Logic that's more than a line or two lives in files the owner can also run locally (`scripts/ci/*.sh`, `packages/db/scripts/check-migration-order.ts`), so the YAML only wires them together. All five jobs become required status checks in the `protect-main` ruleset (ADR 0017).

**Tech Stack:** GitHub Actions on `ubuntu-latest`; actions pinned to commit SHAs: `actions/checkout` v7.0.1, `actions/setup-node` v7.1.0, `pnpm/action-setup` v6.1.0 (supports pnpm 12, reads `packageManager`), `docker/setup-buildx-action` v4.4.1, `docker/build-push-action` v7.4.0 (GitHub Actions layer cache, `type=gha`); gitleaks v8.30.1 and actionlint 1.7.12 as Docker images pinned by digest; Testcontainers (already used by the tests); Node 24 type stripping to run a `.ts` script with no build; Dependabot version updates for actions.

**Spec:** `docs/PROGRESS.md` task P0.6 (including the notes from P0.4 and P0.5); ADRs 0012 (CI/CD), 0013 (testing), 0017 (git workflow, ruleset), 0021 (migration-order trap); `docs/devops/secrets.md` rule 4 (CI).

## Global Constraints

- Triggers: `pull_request`, `push` to `main`, `workflow_dispatch`. **Never `pull_request_target`.** No repository secrets are used by CI at all.
- Workflow-level `permissions: contents: read`; no job gets more.
- Every third-party action is pinned to a full 40-character commit SHA with the tag in a comment (`# v7.0.1`). Docker images used as tools are pinned by digest.
- Every job has `timeout-minutes`. `concurrency` cancels an older run of the same PR or branch.
- No `${{ github.event.* }}` value is ever written inside a `run:` script; it goes through `env:` (script injection).
- Node 24, pnpm from `package.json` `packageManager` (12.16.1). `pnpm install --frozen-lockfile`.
- Required check names (job ids) are exactly: `check`, `secrets`, `pr-title`, `migrations`, `smoke`.
- Branch `ci/p0.6-ci`; Conventional Commits; gitleaks staged scan + personal-data `git grep` before each commit (`docs/devops/git-workflow.md`). **No AI attribution lines** in commits or the PR (`CLAUDE.md` rule 6).
- Owner decided (2026-10-31): Claude pushes the branch and opens a draft PR to iterate on CI; Claude sets the required checks with `gh api` once CI is green, and documents the click path for the owner.

## Decisions in this plan (and why)

| Decision | Why |
| --- | --- |
| Integration tests use Testcontainers in CI, not a `services: postgres` container | Same code path as the laptop (ADR 0013), and the bootstrap roles script runs exactly as in `compose.yaml`. ADR 0012's "PostgreSQL service container" line is refined by ADR 0024. |
| PR-title check is a 20-line bash script, not a marketplace action | No third-party code with access to the PR; teaches the env-variable rule against script injection. |
| gitleaks runs from its Docker image, same version as the local command | One tool, one version, everywhere; no licence questions (gitleaks-action needs one for organisations). Local command bumped from v8.28.0 to v8.30.1. |
| Smoke job builds images with `docker/build-push-action` (`load: true`, `cache-from/to: type=gha`), then `docker compose up --no-build` | Compose's own `--build` can't use the GitHub cache; the image tags match `compose.yaml` (`business-software-app:local`, `business-software-web:local`). |
| No push trigger for feature branches | A branch with a PR would run twice; the owner always opens a PR. |
| Dependabot only for `github-actions`, monthly | Keeps SHA pins from going stale. npm updates stay manual (one-day `minimumReleaseAge`, ADR 0018). |

## Review Focus

1. A PR title containing `$(…)`, backticks or quotes: checked as text, never executed. Pinned in Task 2's cases.
2. Titles that look almost right: capital first letter, trailing full stop, unknown type, missing space after the colon, over 72 characters, `feat!:` and `feat(api)!:`: each gets the right verdict. Pinned in Task 2's cases.
3. A PR that adds no migration, or a base branch with no journal file: the migration check passes. Pinned in Task 1's tests.
4. A service that fails to start in the smoke job: the job fails within its timeout and the container logs are printed. Checked in Task 4 by a deliberate failing push.
5. A first run with an empty layer cache: the smoke job still passes, just slower; the second run is faster. Checked in Task 4 by comparing two runs.

### Task 1: Migration-order check

**Files:**
- Create: `packages/db/scripts/check-migration-order.ts`
- Test: `packages/db/scripts/check-migration-order.test.ts`
- Modify: `packages/db/tsconfig.json` (`include` gets `"scripts"`)

**Interfaces:**
- Produces: `findOutOfOrderMigrations(base: readonly JournalEntry[], head: readonly JournalEntry[]): string[]` where `interface JournalEntry { tag: string; when: number }`: the tags in `head` but not in `base` whose `when` is not greater than the newest `when` in `base`, in `head` order.
- Produces (CLI, used by Task 3's workflow): `node packages/db/scripts/check-migration-order.ts <base-ref>`. It reads `git show <base-ref>:packages/db/migrations/meta/_journal.json` (missing → empty list) and the working-tree journal; exit 0 with `Migration order OK`, or exit 1 naming each out-of-order tag and telling the author to rebase, delete their migration and run `pnpm db:generate` again (`docs/devops/git-workflow.md`). The CLI runs only when `import.meta.main`. No imports except `node:` built-ins (Node runs the file with type stripping, no build).

- [ ] **Step 1: Write the failing tests** — `describe('findOutOfOrderMigrations')`:
  - `returns nothing when the PR adds no migration` (base = head = two entries → `[]`)
  - `accepts a new migration newer than every one on main` → `[]`
  - `rejects a new migration older than the newest on main` → `['0001_old']`
  - `rejects a new migration with the same timestamp as the newest on main` → `[tag]`
  - `accepts any migration when main has none` (base `[]`) → `[]`
  - `reports only the old one of two new migrations` → `['0002_old']`
- [ ] **Step 2: Run** `pnpm --filter @business-software/db exec vitest run scripts` — expected FAIL (module not found).
- [ ] **Step 3: Implement** the function and CLI.
- [ ] **Step 4: Run** the tests → PASS. Then `node packages/db/scripts/check-migration-order.ts main` → `Migration order OK`, exit 0. Check a failure by hand: a temporary journal edit giving `0000` a later `when`, run against `main`'s journal with a fake old entry added; then revert.
- [ ] **Step 5:** `pnpm lint && pnpm typecheck`, then commit `ci(db): add a check that new migrations are newer than main's`.

### Task 3: Smoke script, workflow and Dependabot

**Files:**
- Create: `scripts/ci/smoke.sh` (executable)
- Create: `.github/workflows/ci.yml`
- Create: `.github/dependabot.yml`
- Modify: `docs/devops/git-workflow.md` (gitleaks version in the two local commands → v8.30.1, same digest as CI)

**Interfaces:**
- Consumes: Task 1's CLI, Task 2's script.
- `scripts/ci/smoke.sh` expects `pnpm app:up`'s containers to be running (started by the workflow, or by hand locally). `set -euo pipefail`. Checks, each printing `ok: …` or failing with what was expected vs got:
  1. `GET :3000/api/health/ready` → 200.
  2. `GET :8080/api/health/ready` → 200 with `content-type: application/json`.
  3. `HEAD :8080/` → 200, `cache-control: no-cache`, a `content-security-policy` header.
  4. `HEAD :8080/no-such-page` → 200.
  5. `HEAD :8080/assets/missing.js` → 404, `cache-control: no-store`.
  6. `docker compose run --rm --no-deps -e MIGRATION_DATABASE_URL=postgresql://app_owner:wrong@db:5432/business_software migrate` → exit 1.
  7. `docker compose stop`, then `docker inspect -f '{{.State.ExitCode}}'` of `api`, `worker` and `web` → 0 each.
- `ci.yml` jobs (all `runs-on: ubuntu-latest`):
  - `check` (20 min): checkout → `pnpm/action-setup` → `setup-node` (`node-version: 24`, `cache: pnpm`) → `pnpm install --frozen-lockfile` → `pnpm format:check` → `pnpm lint` → `pnpm typecheck` → `pnpm test` → `pnpm build` → actionlint (Docker, workspace mounted read-only).
  - `secrets` (5 min): checkout with `fetch-depth: 0` → gitleaks `git /repo --redact -v` (Docker, read-only mount, `safe.directory` passed through `GIT_CONFIG_COUNT/KEY/VALUE` env, because the container's user doesn't own the runner's files).
  - `pr-title` (2 min, `if: github.event_name == 'pull_request'`): checkout → `scripts/ci/check-pr-title.sh` with `PR_TITLE: ${{ github.event.pull_request.title }}` in `env:`. Triggers include `pull_request` types `opened, edited, synchronize, reopened`, so renaming the PR re-runs it.
  - `migrations` (2 min, PR only): checkout with `fetch-depth: 0` → `node packages/db/scripts/check-migration-order.ts origin/${{ github.base_ref }}` (base_ref through `env:`).
  - `smoke` (20 min): checkout → `cp .env.example .env` (fake passwords, throwaway database) → buildx → build `apps/api/Dockerfile` as `business-software-app:local` (cache scope `app`) and `apps/web/Dockerfile` as `business-software-web:local` (scope `web`), `load: true`, `mode=max` → `docker compose up -d --wait --no-build` → `scripts/ci/smoke.sh` → on failure, `docker compose logs --no-color`.
- `dependabot.yml`: `package-ecosystem: github-actions`, `directory: /`, `interval: monthly`, commit prefix `ci`.

- [ ] **Step 1:** Write `smoke.sh`; run it locally in Git Bash after `pnpm app:up` → every check `ok` (check 7 may differ on Windows, the reason it moves to CI; note what happens).
- [ ] **Step 2:** Get the gitleaks and actionlint image digests (`docker buildx imagetools inspect`); write `ci.yml` and `dependabot.yml`.
- [ ] **Step 3:** Run actionlint locally in Docker → no findings. Run the full-history gitleaks command locally with v8.30.1 → no leaks.
- [ ] **Step 4:** Commit `ci: add the github actions workflow and dependabot for actions`; `git push -u origin HEAD`; `gh pr create --draft` with title `ci: add github actions ci with smoke tests and required checks (P0.6)` and the filled template.
- [ ] **Step 5:** Watch the run (`gh pr checks --watch`); fix and push until all five pass. Each fix is its own `fix(ci)`/`ci` commit, and each surprise goes in the interview log.
