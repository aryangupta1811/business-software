# P0.7 Design System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the web app its Apple-clean look (tokens, IBM Plex, light/dark), seven base components, the app layout, a keyboard-shortcut module with a help panel, a favicon and a `/design` showcase page, all inside the existing CSP.

**Architecture:** Tokens are CSS custom properties in `styles.css` (`:root` light, `.dark` dark) mapped into Tailwind 4 with `@theme inline`; Tailwind's default colour and text scales are removed so only tokens can be used. Components are shadcn/ui source copied by hand into `src/components/ui/`. The theme is a `dark` class on `<html>` set before first paint by an external `public/theme-init.js`. Shortcuts are a small registry plus a React provider that listens on `window`; the help panel is a native `<dialog>`.

**Tech Stack:** React 19, Tailwind 4, `@fontsource/ibm-plex-sans` and `@fontsource/ibm-plex-sans-devanagari` 5.3, `lucide-react`, `@radix-ui/react-tooltip`, `class-variance-authority`, `clsx`, `tailwind-merge`, Vitest + Testing Library (jsdom), TanStack Router `staticData`, i18next `ParseKeys`.

**Spec:** `docs/plans/2026-10-31-p0.7-design-system-design.md` (owner-approved 2026-10-31). Also ADR 0003 (shadcn/ui on Radix), ADR 0023 (Caddy, CSP, three languages).

## Global Constraints

- Branch `feat/p0.7-design-system` (exists). Conventional Commits; before each commit run the staged gitleaks scan and the personal-data `git grep` (`docs/devops/git-workflow.md`, Secrets). **No AI attribution lines** (`CLAUDE.md` rule 6).
- CSP is unchanged: `script-src 'self'; style-src 'self'; font-src 'self'; img-src 'self' data:`. No inline `<script>`, no `<style>` or `style="…"` in HTML, no runtime-injected `<style>` elements, no external URLs.
- Every user-visible string is in `en.json`, `hi.json` and `hi-Latn.json`; Hindi values contain Devanagari, Hinglish values contain none (`locales.test.ts`). Key-cap labels (`Alt`, `H`, `F2`), token names and made-up sample data on `/design` are not UI text and stay in code.
- Text never below 13 px; body 15 px. Radius: `rounded-lg` (8 px) for cards, buttons, inputs, nav items; `rounded-md` (6 px) badges; `rounded-sm` (4 px) key chips.
- New dependencies go in `apps/web/package.json`; pnpm's one-day `minimumReleaseAge` picks the newest allowed version (lucide-react 1.66.0 is from today, so an older one installs — expected).
- Never write files with PowerShell `Set-Content`/`Out-File`; no bare `cat > file` before a heredoc.
- `pnpm check` passes at the end of every task.

## Review Focus

1. **Holding a key down** (a shopkeeper keeps `F2` or `Alt+H` pressed): auto-repeat events fire nothing → test in Task 4.
2. **Hindi phonetic IME** (typing Hindi in a field with an IME active): keydowns during composition fire nothing → test in Task 4.
3. **AltGr layouts** (`Ctrl+Alt` arrives together): `Ctrl+Alt+H` does not trigger `Alt+H` → test in Task 4.
4. **Shortcuts while the help panel is open** (`Alt+H` pressed with help showing): nothing fires; `Esc` closes help → test in Task 4.
5. **React StrictMode double mount** (dev mounts, unmounts, remounts every component): registering in an effect never reports a false clash → test in Task 4.

Also checked by hand in Task 7: long Hindi labels in the sidebar and top bar at 1024 px wide don't overflow or clip.

**Files:**

**Interfaces:**
- Consumes: `Kbd`, `KbdGroup`, `Button` (Task 2).
- Produces:
  - `keys.ts`:
    - `type KeyCombo = { ctrl: boolean; alt: boolean; shift: boolean; key: string }`, where `key` is `F1`–`F12`, `Escape`, `?`, `KeyA`–`KeyZ` or `Digit0`–`Digit9`.
    - `parseKeys(keys: string): KeyCombo`, for `'F2'`, `'Alt+H'`, `'Ctrl+Shift+K'`, `'?'`, `'Escape'`. It throws on: an unknown key; a letter or digit without `Ctrl`/`Alt`; a reserved combo (`F5 F11 F12 Ctrl+T Ctrl+W Ctrl+N Ctrl+R Ctrl+L`).
    - `matches(combo: KeyCombo, event: KeyboardEvent): boolean`.
    - `isTypingTarget(target: EventTarget | null): boolean`: true for `input`, `textarea`, `select`, `[contenteditable]`.
    - `keyLabels(keys: string): string[]` (`'Alt+H'` → `['Alt', 'H']`) for `KbdGroup`.
  - `registry.ts`:
    - `type ShortcutGroup = 'general' | 'navigation'`.
    - `interface Shortcut { keys: string; description: ParseKeys; group: ShortcutGroup; action: () => void }`.
    - `class ShortcutRegistry { register(shortcut: Shortcut): () => void; active(): readonly Shortcut[]; handle(event: KeyboardEvent): boolean; subscribe(listener: () => void): () => void }`.
  - `shortcut-provider.tsx`:
    - `ShortcutProvider({ children })`: creates one registry, adds a `window` `keydown` listener that calls `handle` and `preventDefault()`s when it returns true, and registers `?` → open help (group `general`).
    - `useShortcut(shortcut: Shortcut): void`: registers in `useEffect`, keeping the latest `action` in a ref so re-renders don't re-register.
    - `useActiveShortcuts(): readonly Shortcut[]`: `useSyncExternalStore`.
  - `shortcut-help.tsx`: `ShortcutHelp({ open, onClose })`, a native `<dialog>`.
  - Locale keys: `shortcuts.title`, `shortcuts.close`, `shortcuts.groups.general`, `shortcuts.groups.navigation`, `shortcuts.openHelp`, `shortcuts.goHome`.

**Matching rules** (`registry.handle`; this is the algorithm the tests pin):
1. Return false if `event.repeat` or `event.isComposing`, or if help is open and the key isn't `Escape` (the provider passes help state in; the dialog handles `Escape` itself).
2. Letters and digits compare `event.code` with `combo.key`; `F1`–`F12`, `Escape` and `?` compare `event.key`.
3. `ctrl` and `alt` must equal `event.ctrlKey`/`event.altKey` exactly. `shift` must match exactly, except for `?` (which needs Shift on most layouts and ignores it).
4. If `isTypingTarget(event.target)` and the combo has no `ctrl`/`alt` and its key isn't `F1`–`F12` or `Escape`: return false.
5. `register` throws `Shortcut "<keys>" is already registered` when an equal `KeyCombo` is active; the returned function removes exactly that registration.
